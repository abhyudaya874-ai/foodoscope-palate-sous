# Deck outline — Palate + Sous (8 slides mapped to the round-1 rubric)

1. **Idea** — Palate: gamified profile layer (data-true cards, streak borders, ranks). Sous: an autonomous agent that probes the Foodoscope APIs, proves contract drift, ships verified fixes. Tagline: "proof over polish — every number traces to an event."
2. **Problem** — API consumers can't trust docs: param names drift, types lie, name spaces don't join across DBs. Teams burn trial tokens rediscovering this. (Cite only PROOF.md examples: `naturalSource`→`natural_source_name`; string-encoded `Calories`.)
3. **Users** — hackathon teams on the Foodoscope trial wallet (measured 25 req/window), and integrators who need regression tripwires after v1.
4. **How it helps** — one replayable run produces: inferred OpenAPI, confirmed-bug list with curls, a mergeable client shim, a crosswalk CSV, and a mail-ready bug report. The card gamifies the audit so teams keep probing.
5. **Similar products + key difference** — API monitors (e.g. contract testers) detect; Sous verifies end-to-end: no repro, no bug; no failing→passing test, no verified fix. Everything derives from an append-only event log. Say "documented", never "only".
6. **Practicality & scalability** — Next.js + local files, zero external DB; budgets hard-capped (BUDGET.json: 40 tool calls, wallet cap); record/replay makes demos deterministic offline; multi-provider LLM gateway with measured fallback (Groq live; OpenRouter/NVIDIA keys present, fallback on 402/404).
7. **Endpoints** — `api.foodoscope.com` Bearer auth; `/recipe2-api/recipe-bytitle/recipeByTitle`, `/flavordb/entities/by-natural-source` probed live; 39 further FlavorDB paths documented in `workspace/openapi.inferred.yaml` (Postman-sourced, marked unverified).
8. **Proof** — the numbers slide: 3 live API calls · 3 confirmed bugs (evidence-linked) · 2 fixes verified failing→passing · crosswalk 9→13/30 · rate limit measured 25/window · `pnpm demo:replay` runs it all offline. Source: `PROOF.md`, regenerated by `pnpm proof`.
